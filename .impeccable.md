# Design context

This file is the persistent design brief for the Ethereum P2P Observatory. Any skill that generates UI code, documents, or visual artefacts for this project must adhere to it. Keep it current; update in place when conventions change.

## Design context

### Users

Technical engineers working on Ethereum p2p networking, consensus clients, builders, relays, and researchers studying the network. They arrive with a specific question ("did block 12345678 propagate slowly?", "how did blob inclusion trend this week?") and want to answer it without friction. They read dense data and cross-reference across time; they are comfortable with mono fonts, keyboard navigation, and terminal-adjacent interfaces. They are not impressed by polish for polish's sake; they are impressed by a tool that respects their intelligence and their time.

### Brand personality

Three words: **rigorous, precise, unhurried.**

- **Rigorous** in that numbers are exact, units are labelled, axes are honest, and nothing is rounded or prettified without saying so.
- **Precise** in that every typographic and chromatic choice is intentional; there is no decoration, and every element earns its pixel budget.
- **Unhurried** in that the interface does not pressure, animate, or shout. It waits to be read.

### Emotional goal

Quiet authority. The interface should feel like an instrument panel, not a marketing dashboard. A reader should come away with confidence that the data is trustworthy and the presentation is not manipulating their attention.

### Aesthetic direction

Reference: `~/W/ethereum/wiretap/dashboard`, light theme. Terminal-adjacent, documentary, densely typographic. Warm paper-coloured background; mono type for all technical content; 1-pixel borders; zero radii; no shadows, no gradients on chrome.

**Anti-references** (explicitly not this):

- Generic SaaS dashboards: Datadog, New Relic, Grafana defaults, gradient cards.
- Corporate BI: Tableau, Power BI, Looker.
- Cheerful consumer data viz: Google Trends, Spotify Wrapped style.
- Glassmorphism, neumorphism, rounded-corner brand colour splashes.

### Design principles

1. **Data before chrome.** Every non-data pixel earns its place. If an element doesn't help the reader answer their question, remove it.
2. **Dense but legible.** Small type is fine; illegible type is not. WCAG AA minimum on every text colour against its background.
3. **Monospace for numbers.** All numeric, technical, and addressable content is rendered in `Xray Mono`. Sans reserved for prose (context cards and about-style pages).
4. **Zero radii, one-pixel borders.** Square corners everywhere. Visual separation is always a rule or a border, never a shadow.
5. **Colour is information, not decoration.** Chroma is reserved for categorical encodings in charts and for accent states. UI chrome is achromatic warm neutrals.
6. **Motion is minimal and deliberate.** Transitions are 180 ms, `ease-out`, on `background-color` and `border-color` only. Pane transitions use Framer Motion for scale+opacity. No parallax, no bouncy springs, no hover lifts.

### Typography

Fonts:

- Sans (`--b`): `'IBM Plex Sans', system-ui, sans-serif`: reserved for prose (context cards, about page, short-form body text).
- Mono (`--m`): `'Xray Mono', monospace`: primary face for data, labels, chart titles, pane headers, controls, and any numeric content.

Scale:

- `--t-xs`: 10 px: axis ticks, tertiary labels, micro-UPPERCASE section tags.
- `--t-sm`: 12 px: attributes, control labels, kbd hints, pill text, button text.
- `--t-md`: 13 px: primary data, slot numbers, pane titles, totals.
- `--t-lg`: 16 px: page and section titles.

Tracking and leading:

- `--track-caps`: `0.06em` for all-caps labels.
- `--lh-dense`: 1.2 for compact rows, labels, control text.
- `--lh-body`: 1.4 for prose.

Globals:

- Tabular numerals via `font-feature-settings: 'tnum'` on `#root`.
- `-webkit-font-smoothing: antialiased`.
- `font-kerning: normal`.

### Typography compositions

- **Page / section title**: mono, `--t-lg`, weight 700, `--hi`, `--track-caps`.
- **Data value (large)**: mono, `--t-md` or `--t-lg`, `--fg`, tabular numerals.
- **Micro label (UPPERCASE)**: mono, `--t-xs`, `--3`, `--track-caps`.
- **Attribute / control label**: mono, `--t-sm`, `--3`.
- **Button text**: mono, `--t-sm`, `--fg`.
- **Prose (context card)**: sans, `--t-sm`, `--fg`, `--lh-body`.
- **Kbd**: mono, `--t-sm`, `--3`, `--0` fill, 1px `--2` border, padding `0 4px`.

### Spacing

8-px grid; step sizes `0 · 2 · 4 · 8 · 12 · 16 · 24 · 32`. Use the smaller values for internal pane chrome, larger values for section separation.

- Interactive hit target minimum: 28 px in the constrained dimension.
- Pane gutter (between sibling panes): 1 px (the `react-mosaic` rule).
- Section padding: 16 px horizontal, 12 px vertical.
- Cell padding: 8 px horizontal, 4 px vertical.
- Text field padding: `4px 8px`.
- Button padding: `4px 10px` (text), 28 × 28 px (icon-only).

### Borders and radii

- **Radius: 0 everywhere.** Tailwind `borderRadius: { DEFAULT: '0', none: '0' }`; no exceptions.
- **Borders**: 1 px solid `--2`. This is the default separator. Never use a `box-shadow` for elevation or separation.
- **Rules**: same 1 px `--2` hairline, full-bleed within panels, 8 px margin above / below sections.

### Focus

- Keyboard focus ring: `outline: 1px solid var(--fg); outline-offset: -1px;` (inset). Applied via `*:focus-visible`.
- No browser-default blue outline.
- Hover state is a background fill (`--hover`), never a lift or shadow.
- Active / selected state: `--sel-bg` fill plus `--sel-border` outline.

### Iconography

- **Lucide icons only**, via the project's existing `Icon` component wrapper.
- **No emoji** in UI copy or generated content.
- Icon sizes: 14 px next to `--t-sm` or `--t-md` text, 16 px next to `--t-lg`, 12 px for inline micro-UI.
- Icons inherit `currentColor` by default; explicit fill only for status indicators.

### Scrollbars

- Webkit: 2 px wide; thumb `--2`; track `--0`.
- Firefox: `scrollbar-width: thin; scrollbar-color: var(--2) transparent;`.

### Motion

Durations and easings:

- UI chrome transitions (background, border): 180 ms, `ease-out`.
- Pane transitions (scale, opacity) via Framer Motion: 180 ms, `ease-out`.
- No transform animations on UI chrome (no hover lifts, no shimmers, no pulses except where explicitly defined below).

Defined animations (already specified in `index.css` of the wiretap dashboard; port as-is):

- `@keyframes blink`: opacity pulse for live indicators.
- `@keyframes slot-enter`: opacity + 4 px `translateY` fade-in for newly-arrived rows.
- `@keyframes traffic-pulse`: colour pulse between `--3` and `--fg` for activity markers.

Reduced motion:

```css
@media (prefers-reduced-motion: reduce) {
  *, *::before, *::after {
    animation-duration: 0.01ms !important;
    animation-iteration-count: 1 !important;
    transition-duration: 0.01ms !important;
  }
}
```

## Chart theming (Apache ECharts)

A single ECharts theme derived from the tokens above, registered at app start.

- Background: transparent (inherits page `--0`).
- Axis line: `--2`.
- Axis tick: `--2`.
- Axis label: `--3` at `--t-xs`, mono.
- Split line: `--2` at 0.35 opacity.
- Text color: `--fg`.
- Title: mono, `--t-md`, `--hi`.
- Legend: mono, `--t-xs`, `--fg`.
- Tooltip: background `--1`, border 1px `--2`, text `--fg`, no radius, no shadow.
- Series categorical: `--accent-amber`, `--accent-teal`, `--accent-green`, `--accent-purple`, then the dynamic HSL palette.
- `visualMap` continuous scale for sequential data: single-hue ramp from `--0` to one accent; for diverging data, accent-purple to accent-amber via `--1`.
- Heatmap: canvas renderer with `progressive: 5000, progressiveThreshold: 10000` for dense grids.
- DataZoom: `--2` handles, `--1` background.

## Component strategy

Single source of primitives: **shadcn/ui** for every commodity component, re-themed via the Tailwind token config and a small overrides layer. Hand-rolled code is reserved for project-specific composites.

### shadcn components (all primitives)

Install via `npx shadcn@latest add <name>`. Each gets: radius 0, no shadow, `--2` border, `--0` or `--1` surface, `--fg` text, mono font (for technical content) or sans (for prose), 1-px-inset focus ring, 180 ms `ease-out` transitions.

- `button` · `input` · `label` · `badge` (used as "pill" via variants for sidebar topic filters) · `separator` · `tabs` · `toggle` · `switch` · `kbd`
- `dialog` · `popover` · `tooltip` · `dropdown-menu` · `context-menu` · `command` (for Cmd-K, paired with `uFuzzy`) · `scroll-area`

### Hand-rolled composites (project-specific only)

In `site/src/workspace/` and its subdirectories:

- `Workspace` (root island)
- `PaneTree` (wraps `react-mosaic-component`)
- `Pane` · `PaneHeader` · `ContextCard` · `ChartBody` · `PlotRenderer` (ECharts mount)
- `Sidebar` · `CommandPalette` (shell combining shadcn `Command` + uFuzzy + registry lookups)
- `DatePicker` · `MobileNav` · `Header`

No commodity primitive is hand-rolled. If you catch yourself writing a `Button.tsx`, stop and adopt shadcn's.

### Variant conventions

For shadcn Badge used as filter pill:

```tsx
<Badge variant="outline" className="uppercase tracking-caps text-xs font-mono">
  Blob inclusion
</Badge>
```

Active state flips the variant or adds `className="bg-sel-bg border-sel-border"`.

For shadcn Button in pane headers and toolbars: `variant="ghost"` by default (no border) with hover `--hover`; `variant="outline"` when the button needs a persistent border.

## Accessibility

Non-negotiable constraints:

- **WCAG AA minimum** for every text-on-background pairing. The `--3` bump from `#9e9585` to `#7a7165` reflects this rule; never introduce new text colours without verifying 4.5:1 for small text and 3:1 for large.
- **Keyboard reachable**: every interactive control accessible via Tab; overlays close with Escape; Enter activates.
- **`prefers-reduced-motion`**: all animations collapse to 0.01ms.
- **Colour-independent**: no information conveyed by colour alone. Every categorical colour has a label, pattern, or positional cue.
- **`aria-label` on every icon-only control.**
- **Focus visible always**: the inset 1 px `--fg` ring is universal.
- **Screen reader text** for live regions (workspace loads, date changes, error states).

## Anti-patterns (do not introduce)

- Rounded corners on any UI element.
- `box-shadow` on UI chrome (allowed inside chart marks or data visualisations only).
- Gradients on UI chrome (allowed inside chart gradients and marks).
- Emoji in UI copy, generated markdown, or commit messages.
- Non-mono typography for numeric or technical data.
- Text colour combinations under WCAG AA for small text.
- Decorative illustrations, mascots, or generic tech imagery.
- Large hero sections or marketing-style layouts.
- Colour alone as information conveyance.
- Hover lifts, hover shadows, hover scales, bounce animations, parallax, hover-only reveals that are inaccessible via keyboard.
- shadcn defaults left un-themed (must pass through the token layer).

## Documentation style rules

Applies to all `.md` files, PR descriptions, commit messages, and generated in-file comments:

- **No em dashes.** Use colons, parentheses, commas, semicolons, or separate sentences.
- **Sentence case for headings.** Capitalise the first word and proper nouns only. Acronyms (URL, API, CSS, JSON, HTML, HTTP) stay uppercase.
- **Conventional commits** for git commit subjects.
- **No emojis.**
